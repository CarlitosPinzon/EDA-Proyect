# ADR-005 — .NET 10 LTS con Minimal APIs, Worker Services, YARP y Polly

**Estado:** Aceptado

## Contexto
El backend debe exponer HTTP al cliente y ejecutar consumidores de larga duración.

## Decisión
- .NET 10 LTS (soporte hasta noviembre de 2028).
- APIs con Minimal APIs (Catálogo, Reservas); procesadores como Worker Services con `BackgroundService` (Inventario, Pagos, Notificaciones). Los workers solo exponen `/health` dentro de la red de Docker.
- API Gateway con **YARP** sobre ASP.NET Core: validación JWT y *rate limiting* con el mismo middleware del resto de servicios. Para el taller, el gateway también emite tokens de demostración (`POST /api/auth/token`); en producción ese papel lo cumple un proveedor de identidad (OpenID Connect).
- Clientes oficiales `Confluent.Kafka` y `Elastic.Clients.Elasticsearch` 9.5.
- Arquitectura hexagonal interna: el dominio no depende de Kafka ni de Elasticsearch.
- Resiliencia hacia la pasarela con **Polly** (`Microsoft.Extensions.Http.Resilience`): timeout de 3 s por intento, 3 reintentos con backoff exponencial y *jitter*, *circuit breaker*.

## Alternativas
.NET 11 (STS, soporte más corto); MassTransit (comercial desde la v9 y oculta los conceptos que el taller busca evidenciar); Kong, Traefik u Ocelot como gateway.

## Consecuencias
- (+) Rendimiento, inyección de dependencias, resiliencia y observabilidad integradas.
- (−) Sin Kafka Streams: el procesamiento con estado se hace en el servicio.
